# 2026-10-28

## Implementación de la capa Song (DAL/BLL) + página Song.aspx

- Se replicó el patrón de la entidad `User` (DAL/BLL/Entities) para `Song`, apuntando a `TBL_SONG`
  (`ID_SONG`, `SONG_NAME`, `SONG_PATH`, `PLAYS`).
- Archivos nuevos:
  - `Entities/Song.cs` — ID, SongName, SongPath, Plays.
  - `DAL/Song.cs` — Save, Read, ReadById, Update, Delete, CheckExistSong, IncrementPlays.
  - `BLL/Song.cs` — envoltorio de DAL + `ValidationsRequired` / `ValidationsDuplicated`.
  - `Song.aspx` + `Song.aspx.cs` + `Song.aspx.designer.cs` — lista de canciones, reproductor
    HTML5, nombre del usuario logueado (Session[Constants.USER]), botón Log out, panel admin
    para subir MP3 (usa `FileManagement.SaveSongOnServer`).
  - `PlayCounter.ashx` (+ `.cs`) — endpoint mínimo que incrementa `PLAYS` sin postback
    (un postback cortaría el audio).
- `Web.config`: `songFolderPath` corregido de `../songFiles/` a `~/SongFiles/`
  (con `../` `Server.MapPath` lanza excepción por salir del directorio raíz de la app).
- `WebAppPoliMusicV2.csproj`: se registraron `Song.aspx`, `PlayCounter.ashx`, y los `Compile`
  de `Entities/Song.cs`, `DAL/Song.cs`, `BLL/Song.cs`, `Song.aspx.cs`, `Song.aspx.designer.cs`,
  `PlayCounter.ashx.cs`.
- Nota: el proyecto declara `TargetFrameworkVersion v2.0`; se evitó C# 7+ (sin interpolación,
  sin local functions) en el código nuevo. No fue posible compilar desde la CLI (compilador
  bloqueado por política del entorno), verificado por revisión estática + XML del .csproj.
